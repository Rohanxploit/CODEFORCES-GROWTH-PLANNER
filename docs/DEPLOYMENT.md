# Deployment

Target setup: **MongoDB Atlas** (database), **Render** (API, `render.yaml`), **Vercel** (frontend, `vercel.json`). Vercel serves the static app and rewrites `/api/*` to Render, so the browser only talks to one site and the session cookie is first-party (`SameSite=Lax`).

> This setup is running at https://codeforces-growth-planner-fj1f.vercel.app with the API on Render.

## 1. MongoDB Atlas

1. Create a free M0 cluster.
2. **Database Access:** add a user with read/write access to one database (e.g. `codeforces-growth-planner`).
3. **Network Access:** allow Render to connect. On the free tier Render has no fixed outbound IPs, so allow `0.0.0.0/0` and rely on a strong password, or use a paid Render plan with static IPs.
4. Copy the connection string: `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/codeforces-growth-planner?retryWrites=true&w=majority`.

## 2. Render (API)

1. Push the repository to GitHub.
2. In Render: **New → Blueprint**, select the repository. Render reads `render.yaml`.
3. Set the variables marked `sync: false`:
   - `MONGODB_URI`: the Atlas string
   - `CORS_ORIGINS`: your Vercel URL, e.g. `https://codeforces-growth-planner.vercel.app` (fill in after step 3 if you don't know it yet)
4. `JWT_SECRET` is generated by Render. `TRUST_PROXY=2` accounts for Vercel's rewrite hop.
5. Deploy and open `https://<service>.onrender.com/api/health`. It should return `"status":"ok"` and `"database":"connected"`.

Build: `npm ci --include=dev && npm run build -w shared && npm run build -w server`. Start: `npm run start -w server`. Health check: `/api/health`.

## 3. Vercel (frontend)

1. In `vercel.json`, replace `https://YOUR-RENDER-SERVICE.onrender.com` with your Render URL and commit.
2. In Vercel: **Add New → Project**, import the repository, keep the **root directory** as the repository root (the config builds `shared` and `client` and serves `client/dist`).
3. No environment variables are needed (`VITE_API_BASE_URL` stays empty).
4. Deploy, then update `CORS_ORIGINS` on Render if needed.

## 4. Smoke test

1. Open the Vercel URL, register, and check you land on onboarding.
2. Look up a Codeforces handle, choose a target and generate a roadmap. The first one fetches and caches the problemset, which takes a few seconds.
3. Record an outcome on today's problems and open Analytics.
4. Reload the page and confirm you are still logged in (the cookie works through the rewrite).

## Notes

- **Cold starts:** free Render services sleep when idle; the first request can take up to a minute.
- **Cookies:** keep `COOKIE_SAME_SITE=lax` with the rewrite. If you serve the frontend from a different site and call Render directly, set `COOKIE_SAME_SITE=none` and `VITE_API_BASE_URL=https://<service>.onrender.com`. Browsers that block third-party cookies will then break login, which is why the rewrite is the default.
- **Logs:** the API writes JSON lines to stdout/stderr, which Render's log viewer collects. Unknown errors are logged with a stack trace and returned to clients as a generic 500.
- **Secrets:** never commit `.env` files. `.gitignore` excludes them, and only `.env.example` is tracked.
- **Scaling:** the auth rate limiter and the Codeforces request queue are per process. Running several API instances needs a shared store for both.
